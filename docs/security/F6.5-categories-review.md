- `guide.reorder_article_categories(uuid[])` y `guide.reorder_articles(uuid, uuid[])`: validan lista completa.

- Retirados el GRANT DELETE y la policy de delete de `article_categories` para `anon` y `authenticated`.

## Verificado
- Lo desplegado coincide con los ficheros (cuerpos idénticos; firma remota `p_id uuid, p_reassign_to uuid DEFAULT NULL`; tres versiones en `schema_migrations`).
- `delete_article_category`: DEFINER, propiedad de postgres, `search_path=''`; EXECUTE solo `postgres` y `authenticated`. `reorder_*` y el trigger: INVOKER con `search_path=''`; `reorder_*` para `postgres`, `authenticated`, `service_role`; trigger solo `postgres`.

- Admin comprobado antes de revelar existencia: un no admin recibe siempre 42501 `admin only`.
- `public` intacto.
- GUC `guide.draft_op`: ningún cliente puede fijarlo; la función lo devuelve a `''`; aun falsificado por un admin en SQL directo, `articles_before_write` solo deja pasar `category_id` (contenido, `noindex`, `is_featured` → PT423; `maintenance` sin `rolbypassrls` → PT423).
- La exención de `updated_at` no sirve para editar contenido (vivo: contenido + `sort_order` → PT423; no vivo: sube `updated_at`).
